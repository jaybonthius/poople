# poople

Read `CONTEXT.md` first. Before changing word lists, the daily calendar or par, read `docs/poople-reference.md`. `docs/build-plan.md` is the approved architecture and build order.

- **Reference apps.** Copy the matching implementation from `/home/jay/Code/getajob` first, then `/home/jay/Code/workbench-go/northstar-pro`, `/home/jay/Code/northstar` and `/home/jay/Code/workbench-go/nichestar`, before inventing replacements: Go with Chi/`net/http`, Templ, Datastar; `web/core` and `web/features/<feature>` packages with module-local `static/styles` and `static/web-components`; Task with tasks named `sqlc`, `templ`, `bundle`, `build`, `check` and `race`. Disclose and get approval for material departures. `/home/jay/Code/northstar-pro` is not a reference app.
- **CQRS.** Commands (submitting a guess) validate on the server, commit to SQLite, notify subscribers and return no HTML. Views are a function of SQLite state, rendered with the same Templ code as the first page load, and sent as full-view morphs over one long-lived SSE connection per page.
- **SQLite owns state.** Words, word links, the calendar, par and player state live in SQLite; memory holds only coordination mechanisms and transient request or render values. Use the `sqlite` skill for schema, migration, query, connection and store work.
- **Hidden calendar.** Responses and signals carry only the current puzzle and what the player has already earned. Never ship future start words, unplayed par or solutions.
- **Frontend.** Read `.pi/docs/html-css.md` for HTML/CSS and `.pi/docs/datastar/docs.md` for Datastar/Rocket. Build with semantic HTML, CSS and Datastar; JavaScript beyond Datastar is a Rocket web component using the pinned free Rocket bundle (`datastar-rocket-1.0.4`, typed in `.pi/docs/datastar/datastar-rocket-1.0.4.d.ts`), with typed props down and events up; page Datastar and Go own requests and application state. Use the `impeccable` skill for UI design work.
- **Generated files.** Change sources and run the owning task: `*_templ.go` from `.templ`, `**/zz/*.go` from SQL and `sqlc.yaml`, bundled `static/styles` and `static/web-components` from sources.
- **Tests** catch plausible failures: wrong ladder validation, wrong calendar day or par, leaked calendar data, lost or duplicated guesses. Use real disposable SQLite and `httptest`; avoid mocks that restate the code.
- **Validation.** Run `task check` and `task race` once they exist; production builds pass with `CGO_ENABLED=0`. Stop development servers you start and confirm they exited.
- **Workflow.** Follow `.pi/docs/development.md`. Questions, research and reviews are read-only. The owner controls commits, pushes and deployment. Keep code direct and the change to the request; ask before adjacent cleanup, dependencies or artifacts.
